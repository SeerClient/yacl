## Notes from the translator

* native field names are the Mojang names in snake_case - check them against the port
* a Java `throw` became a `panic!` (a checked exception in Java is an unwinding panic here; `catch` blocks are `std::panic::catch_unwind`)
* `GsonBuilder.registerTypeHierarchyAdapter(..)`: the generated per-class Gson forms carry Dandelion's five adapters (Color, Component, Style, Identifier, Item); other adapters are not applied
* a port method that returns `Result` is `.unwrap()`ed where Java would throw
* `Minecraft.getInstance()` became `compat::minecraft()`: the Minecraft the game hands its tick events, recorded on the first client tick (it panics if called before that)
* a Java downcast `(T) x` became `x.as_any().downcast_ref::<T>().unwrap()` (a failed cast panics, as Java throws ClassCastException)
* a game object's `font` became `compat::font()` (the port's `Font` view over the font set)
* port methods that take the frame's `&Gl` / the `Minecraft` get `gl_state_manager::gl()` / `compat::minecraft()`
* Java arguments that are the frame's context (a GuiGraphics, a Font, the Minecraft) are dropped where the port takes `&Gl` / the Minecraft itself
* `==` on two objects is IDENTITY in Java; it became `std::ptr::eq` - check the call sites that compare values
* `super.extractRenderState(..)` in a mod screen: the game draws the background and the widgets before the override runs (MODDING.md "Mod screens")
* `super.mouseClicked(..)` & co in a mod screen answer `false`: the game's widget pass runs after an override that answers false (the port's `super` body), not before its own code
* `CompletableFuture.supplyAsync(.., executor)`: the Java executor became `compat::executor` (a new thread per task)
